## Self custody strategies

Firmware on Coldcard used a software RNG instead of the hardware one. Attackers reconstructed seeds and swept wallets starting July 30. Galaxy has ~1,779 BTC from 8,600+ addresses. Updating firmware does **not** repair an existing seed. Move funds to a new seed.

**If you generated a seed on affected firmware**

* [Coinkite migration guide](https://coldcard.com/security/migrate)
* Firmware update only fixes *future* seeds. Create a new seed, then move coins.
* Dice exception: 50+ private rolls (128 bits) or 99+ (~256 bits) mixed in at generation. Uncertain? Migrate.
* A passphrase is not a repair. Migrate anyway.
* [MARA Slipstream: ~9k BTC pulled out of Coldcard multisigs](https://foundation.mara.com/articles/9k-bitcoin-rescued-out-of-coldcard-multisigs)
* [River takeaways](https://river.com/content/coldcard-exploit-takeaways)

**Options for displaced Coldcard users**

Do not replace one single-vendor singlesig with another and call it done.

* **New seed + user entropy:** dice / coin flips / key mash on a *different* device. Verify the backup by wipe-and-restore before sending size.
* **Air-gapped open hardware:** [Jade](https://blockstream.com/jade/)
* **USB/wireless + open firmware:** [Trezor](https://trezor.io/), [Foundation Passport Prime](https://foundation.xyz/), [BitBox](https://bitbox.swiss/) (Dixence firmware 9.26.5 — two severe vulns this month, seeds not stolen)
* **Closed SE:** [Ledger](https://www.ledger.com/) (different crypto stack; SE firmware not independently auditable)
* **Collaborative multisig:** [Casa](https://casa.io/), [Unchained](https://unchained.com/), [AnchorWatch](https://www.anchorwatch.com/), [Nunchuk](https://nunchuk.io/), [Liana](https://wizardsardine.com/liana/), [Bitkey](https://bitkey.world/)
* **DIY signers:** [DIY signing device summit](https://github.com/kdmukai/article-diy-signing-device-summit), [SeedSigner](https://seedsigner.com/), [Krux](https://github.com/selfcustody/krux)

## BTCPay Server: LND macaroons stolen

Unauthenticated remote read of `.macaroon` files. Attackers took control of LND nodes and moved funds. On-chain BTCPay wallets were not the target. Update to 2.4.2 + LND 0.21.1, rotate credentials, audit the node.

## Lightning: CLN binary security release, `--offline`, Boltz, Zeus

CLN confirmed several of the AI-generated CVEs are real. Signed **binaries first**, source embargoed two weeks so attackers cannot reverse the fix before nodes upgrade. Do **not** power the node off. Restart with `--offline` until you install: drops peers (nothing routes in/out/through) but the daemon still watches the chain and can answer a force-close. Previous releases including 26.04 are unsupported. 26.09 still planned late September.

Same month: Boltz and Zeus LSP paused after AI-paced attacks.

* [CLN: upgrade signed binaries or `--offline`](https://x.com/Core_LN/status/2092721104783843551)

## Post-quantum: BIP SHRINCS, QSB spend, DropKick

Yesterday Jonas Nick et al. posted **BIP SHRINCS** — first concrete PQ signature scheme designed for Bitcoin. SHA-256 only. Compact stateful path (548–4619 B) plus a 5777 B stateless fallback. Crypto only; Script BIP still to come. Security proof is TODO.

Also yesterday: StarkWare/Avihu Levy spent a QSB output on mainnet (block 964,199) via MARA Slipstream. No fork. Non-standard, GPU-expensive, research not a wallet feature.

In parallel: DropKick (commit/reveal rescue), libshrincs (WOTS+C with a machine-checked proof), sipa's PQC output-type thread.
